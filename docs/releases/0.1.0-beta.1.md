# `@worldhacker/kasane@0.1.0-beta.1`

Status: planned `beta` prerelease pending required CI, protected release
approval, and registry artifact verification.

## Purpose

This beta freezes the functional scope intended for `1.0` and is suitable for
production evaluation. It is not a production recommendation or the final
stability promise. New P2 features, companion packages, and major API
experiments are excluded from the beta line.

## Install

```bash
npm install @worldhacker/kasane@beta
```

Kasane remains ESM-only and supports Node.js 22 and 24. CommonJS `require()` is
not supported. The unscoped `kasane` package is unrelated to this project.

## Feature-complete scope

- sequential value, file, environment, secret, and custom sources;
- normalization and resource limits for untrusted configuration data;
- replace, deep, shallow, append, and prepend merge rules plus removal;
- origin-only/full provenance, explain, safe lifecycle events, and five-way
  diff;
- function and Standard Schema validation with reconciled provenance;
- central redaction, SHA-256/HMAC fingerprints, immutable snapshots, and safe
  JSON/inspection;
- root and `standard-schema` ESM exports with zero runtime dependencies.

The reviewed export and option baseline is recorded in the
[API freeze checklist](./beta-api-freeze.md). Any post-beta incompatible change
requires evidence of a serious problem, explicit approval, a Changeset, and a
migration note.

## Compatibility evaluation

Packed and registry suites cover backend-service, tool/CLI-like,
test-infrastructure, general JavaScript ESM, and TypeScript NodeNext consumers.
The backend and test-infrastructure projects install the published alpha first
and then upgrade in place to beta. Details and remaining operational risks are
tracked in the [compatibility report](./beta-compatibility.md).

## Known limitations

The complete list remains in [Limitations and non-goals](../guides/limitations.md).
Important constraints include no CJS build, CLI, watcher, provider SDK, YAML or
TOML parser, custom-code sandbox, or granular array diff. Direct raw snapshot
access can expose correctly loaded secrets and must not be logged.

## Feedback

Use the **Beta feedback** issue form for non-sensitive compatibility and API
feedback. Maintainers assign every accepted item an owner, severity, target,
and disposition in the [beta feedback tracker](./beta-feedback.md). Report
security issues only through the private channel in
[SECURITY.md](../../SECURITY.md).

## Release evidence

The protected release record must add the release commit, required CI run,
workflow and registry SHA-256 values, npm integrity and provenance, Node 22/24
registry results, and alpha-to-beta upgrade results. Publication is accepted
only when the workflow and registry archives are byte-for-byte identical and
`beta` points to this version while `latest` does not.
