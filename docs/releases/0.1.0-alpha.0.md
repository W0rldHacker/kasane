# `@worldhacker/kasane@0.1.0-alpha.0`

Status: published to npm as the `next` prerelease on 2026-07-19 after required
CI, trusted publisher registration, and protected release approval.

## Purpose

This alpha validates package installation and Kasane's basic architecture before
feature freeze. It is an evaluation release, not an API stability promise or a
production recommendation.

The unscoped `kasane` registry name belongs to an unrelated package. This project
therefore publishes only as `@worldhacker/kasane` under the maintainer-owned
`worldhacker` npm user scope.

## Install and smoke test

```bash
npm install @worldhacker/kasane@next
```

```js
import { kasane, secret, value } from '@worldhacker/kasane';
import { isStandardSchemaV1 } from '@worldhacker/kasane/standard-schema';

const snapshot = await kasane({
  layers: [
    value('defaults', { server: { port: 3000 } }),
    secret('runtime', { token: 'ALPHA_SMOKE_CANARY' }),
  ],
  provenance: 'full',
});

if (snapshot.value.server.port !== 3000) throw new Error('basic config failed');
if (!isStandardSchemaV1({ '~standard': { version: 1, vendor: 'smoke', validate: () => ({ value: {} }) } })) {
  throw new Error('subpath import failed');
}
if (snapshot.explain('token').value !== '[REDACTED]') {
  throw new Error('secret explanation failed');
}
```

Node.js 22 and 24 are supported. Kasane is ESM-only; CommonJS `require()` is not
expected to work and is not part of this alpha evaluation.

## Evaluation focus

Feedback is requested on:

- friction in the `kasane()` and layer-helper API;
- environment mapping, casing, collision, and coercion semantics;
- the usefulness and safety of `explain()` output;
- root and `standard-schema` package resolution in ESM and NodeNext projects.

Use the alpha feedback issue form or record a result in the
[feedback tracker](./alpha-feedback.md). Security reports must use the private
channel in [SECURITY.md](../../SECURITY.md), not the public tracker.

## Known limitations

The complete list is published in [Limitations and non-goals](../guides/limitations.md).
The most important alpha constraints are:

- no CommonJS build, CLI, watcher, or provider SDK;
- JSON is the only built-in file format;
- arrays are atomic and merge rules use exact paths;
- `snapshot.value` is intentionally raw and may contain secrets;
- custom executable sources, parsers, and validators are trusted code;
- breaking alpha changes remain possible and will include a Changeset plus a
  migration note.
